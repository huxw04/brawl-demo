# 第一版收尾计划

状态：工程实现与完整自动回归完成，进入第一版候选试玩；仍保留三/四人真人长局与三张地图逐图验收  
日期：2026-08-30

## 1. 当前基线

第一批五名英雄、Lab、Bot 战斗、房主权威局域网战斗、大地图、随机安全复活、击杀/助攻/死亡统计、连杀播报、倒计时和结算已经可用。双人真人局域网试玩与自动网络劣化测试均已通过。

第一版不加入客户端预测、回滚、公网大厅、NAT 穿透、房主迁移、断线重连、地图机关和道具。它们不是本轮发布阻塞项。

## 2. F1：3～4 人容量验收

目标不是重新设计协议，而是找出仍隐藏的双人假设。

- 新增一个房主加三客户端的本地多进程自动测试；
- 验证四名玩家的 roster、英雄选择、稳定 actor ID、出生点、统一开局和各自输入所有权；
- 四名角色同时移动、造成伤害、死亡、助攻、复活，并在所有窗口得到一致比分和结算；
- 验证普通客户端中途退出后另外三人继续，房主退出后所有客户端安全返回；
- 检查网络发送量、房主帧率、客户端快照陈旧计数和角色位置误差；
- 自动测试通过后，分别进行一次三人和四人真人局域网试玩。

验收标准：四进程连续运行五分钟无崩溃、无重复角色、无串号操作，最终 K/D/A 和胜者一致；真人试玩中不出现随着人数增加而新增的规律性卡顿。

自动验收进展（2026-08-30）：房主加三客户端已验证四人 roster、唯一 actor/peer ID、各自移动所有权和普通客户端退出后剩余三人继续。第五个进程也会参与连接测试并必须收到明确的“房间已满”，不能落入“找不到房间”的底层连接错误。测试同时发现并修复了四人比分包超过 MTU，以及离线 peer 的 RTT 查询窗口。完整五分钟压力测试和真人局域网试玩仍待执行。

## 3. F2：本机战斗浮字

只显示与本机操作直接相关的数字，避免四人乱斗被全场数字淹没。

- 本机造成伤害：在受击英雄上方显示伤害数字；
- 本机获得治疗：在自己上方显示绿色 `+数值`；
- 不显示其他玩家互殴、其他玩家治疗和无实际生命变化的溢出治疗；
- 同一帧或极短间隔的多段伤害保持可读，可轻微横向错开，不合并战斗结算；
- 浮字向上漂移、轻微缩放并在约 0.8 秒内淡出，不参与碰撞与战斗同步；
- 房主产生包含来源、目标、实际数值和类型的权威表现事件，客户端只过滤和播放，不能通过猜测血量快照反推来源。

颜色建议：普通伤害暖白或浅黄，较高伤害橙色，治疗绿色；第一版不额外区分物理/魔法/真实伤害和暴击。

实现进展（2026-08-30）：`CombatActor.heal()` 已统一吸血、命中回血、击杀回血和持续回血的实际治疗口径；伤害与治疗由房主产生 `combat_feedback` 权威表现事件。表现层仅在伤害来源是本机角色或治疗目标是本机角色时生成世界浮字，多段数字使用五个横向槽位错开并在约 0.82 秒内上浮淡出。离线过滤、溢出治疗、四名回血英雄专项和双进程事件传输测试通过，字号已经人工调至原设计的一半并确认可读。

## 4. F3：三张正式地图

继续使用 `maps/*.json`、轴对齐盒体障碍和同一 `ArenaWorld` 构建器，先追求清晰布局和玩法差异，不在首版引入新的机关系统。

建议地图组：

1. **四方庭院**：近似对称的四人基础图，中心开阔、四侧有短墙与低掩体，作为默认竞技图；
2. **回风峡谷**：环形路线与中央高墙，侧翼通道较宽，强调绕后、钩爪和弹射；
3. **残棋台**：错落短墙组成多个可进出的战斗房间，保留长视线但减少全图远程锁定。

每张图提供 8～12 个稳定出生点，检查所有点位可达、不会出生在碰撞体中，并为近战、远程、位移和穿墙技能保留发挥空间。大厅由房主选择地图，match config 广播 `map_id + map_version`；客户端缺少或版本不符时拒绝开局。

验收标准：三张图均通过解析、碰撞、寻路、出生安全和四人联机一致性测试；每张至少完成一局真人试玩。

实现进展（2026-08-30）：`四方庭院`、`回风峡谷`、`残棋台` 已加入地图目录。房间内由房主选择地图，选择变化会同步到客户端并清除全员准备状态，开局配置继续只广播稳定的 `map_id + map_version`。地图自动测试覆盖 JSON 解析、构建器障碍数量、出生点 45 码净空和从首个出生点到所有其他出生点的寻路可达性；四进程测试已验证房主选择 `回风峡谷` 后四端加载同一地图。布局手感与出生公平性仍需真人逐图验收。

## 5. F4：首轮平衡与发布

前三项完成后再集中改数值，避免地图和人数变化污染平衡结论。

- 固定每局时长、击杀上限和复活时间；
- 记录每名英雄的击杀、死亡、助攻、伤害、承伤和治疗；
- 优先处理明显无解连招、无限续航、超长控制和地图适配极端，不追求首版精确胜率；
- 完成五英雄交叉试玩、导出包验证、中文玩法说明和版本标签。

候选版进展（2026-08-30）：比赛时长、击杀上限和复活流程已经固定；结算状态记录 K/D/A、输出、承伤与实际治疗。第一轮统一生命值区间和数值校准已完成，本轮最终将奶龙「大笑」调整为每次回复 12、褚赢「飞棋」调整为 4 伤害，并将版本握手更新为 `0.4.6-v1-candidate`。完整自动回归、双进程网络劣化及四进程容量测试全部通过；导出包已由两台机器验证可运行。剩余事项属于真人长局和逐地图手感验收，发现问题后再进入下一轮平衡。

## 6. 执行顺序

`F1 四人容量测试 → F2 战斗浮字 → F3 正式地图与选择 → F4 平衡与发布`

先验证多人容量，因为它最可能暴露基础结构问题；浮字随后接入统一权威事件；正式地图建立在已验证的四人规则上；最后才使用稳定人数和地图进行平衡。
