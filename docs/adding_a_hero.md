# 新增英雄工作流

## 1. 准备角色定义

复制占位英雄定义脚本，填写：

- `hero_id`、显示名称和主题色；
- 最大生命、移动速度、体力和能量；
- 3D 碰撞半径、身体高度、Sprite3D 尺寸与视觉锚点；
- 普攻、技能 1、技能 2、大招定义。

不要在通用 `CombatActor` 中加入 `if hero_id == ...`。

## 2. 定义每个技能

至少明确：

- 输入槽位；
- 前摇、有效时间、后摇、冷却；
- 体力或能量消耗；
- 3D 判定体积的宽、深、高和相对角色的位置；
- 伤害、击退和攻击高度；
- 近战判定框或投射物；
- 命中与受击能量收益；
- 动画/特效标签。

技能若施加状态，引用通用 `StatusEffectDefinition`；不要直接修改目标的移动速度、可选中性或输入开关。需要随机结果时使用战斗提供的局部 RNG，禁止调用全局随机函数。

复杂技能应组合通用效果。如果必须新增机制，先判断它是否应成为可复用的效果类型。

## 3. 在角色实验室验收

逐项检查：

1. 待机、移动、跳跃、下落、翻滚；
2. 每个技能的前摇、判定、后摇与冷却；
3. 正面、背面、边缘距离、不同高度和空中目标命中；
4. 资源不足时的反馈；
5. 判定框和画面是否对齐；
6. 子弹的阵营、命中、穿透、撞墙和超时销毁；
7. 受击、击退、无敌与死亡。通用角色已有左右随机倒地；若角色使用 `hat`、`scabbard_back`、`katana_back`、`katana_action` 分层，会自动获得装备落地和刀插地表现。

调参时可以开启“忽略消耗/CD”，但关闭后必须再完整检查一次。

## 4. 在战斗场景验收

- 玩家输入可以稳定触发所有动作；
- 快速连续输入不会跳过合法阶段；
- Bot 使用该英雄时不会卡死或无限重复无效动作；
- HUD 数值和实际资源一致；
- 一局结束后能够正确重置。

## 5. 正式资源接入

将 2D 图片或 Sprite Sheet 放入 Sprite3D，通过 AnimationPlayer/AnimationTree 将动画、音效和 VFX 绑定到技能阶段及战斗事件。表现层不能直接减血或修改冷却。修改正式资源后，重新进行角色实验室的 3D 判定体积对齐检查。
